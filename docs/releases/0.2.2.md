# Postrove 0.2.2

Postrove 0.2.2 adds video reading, local speech transcription, and capability setup to macOS Apple silicon and Windows x64. Platform searches within a topic can run concurrently.

## Search

- Different AI connections search concurrently within a topic. Language experts sharing one connection take turns, while captured replies receive their reading versions independently. Topics keep their admission order.
- Grok reply capture retains complete answers with many inline citations.

## Video reading

- Bilibili reading captures accessible native captions and keeps timestamps tied to the selected video part. Account-accessible captions use the shared browser session.
- YouTube and Bilibili prefer native captions. When captions are absent, they transcribe accessible audio through the local speech service. Xiaohongshu video reading captures the title, written description, cover, and accessible spoken audio.
- Speech results identify application transcription and retain original-media timestamps. Partial results preserve captured metadata and completed transcription chunks for recovery.
- Reading issues identify the source and the observed failure stage. Later translation or introduction failures retain their own processing state alongside saved source content.

## Capability setup

- Settings → Capabilities shows current platform capabilities and opens their configuration requirements. Each requirement links to its setup page.
- Settings → Speech to text downloads and verifies the local model after selecting Install. Installation shows transferred bytes and supports cancellation and retry. The application includes the transcription components; the model download is about 181 MiB.

## Upgrading from 0.2.1

Update through Settings → About, or install the [macOS DMG or Windows EXE](https://github.com/huggon1/postrove/releases/tag/v0.2.2). Reports, reading materials, model connections, settings, and platform sessions remain in the Postrove profile.

Source platforms determine sign-in, verification, caption availability, and media access. YouTube audio retrieval currently uses public media access. Speech transcription covers spoken audio; visual content and text within video frames retain unknown coverage. Recognition quality depends on the source audio and language.

The [installation guide](../../README.md#installation-and-use) describes supported systems and first-open approval. The [release guide](../releasing.md#signing-and-assets) describes signing and update packages.
